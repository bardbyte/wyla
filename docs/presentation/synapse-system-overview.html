Frame

The failure is not SQL.

Point a modern model at a schema and ask for “new accounts approval rate last quarter.” You get syntactically perfect BigQuery. It runs. It returns a number. The number is wrong, and nothing about it looks wrong.

Which definition

Three catalogs in this warehouse define approval rate and disagree on the denominator. The model picks one. Nothing tells it there were three.

What one row means

A join against a table with no declared primary key silently doubles the numerator. The SQL is valid. The grain changed.

What the literal is

WHERE status = 'Approved' returns zero rows, because the warehouse stores 'A'. The query succeeds. The answer is 0.

Whose authority

A mined pattern with 4,000 executions and a certified KPI with 3 look identical to a ranker that scores on usage. Popularity is not governance.

All four are meaning problems, and meaning is not in the schema. It is scattered across a catalog nobody fully trusts, a metadata service that answers DENIED a third of the time, 35,700 SQL fragments people pasted into a wiki over six years, and the query history — the only source that knows what is actually run.

Frame

One commitment. Everything else falls out of it.

Don’t build a better translator. Build a substrate the translator cannot lie about — the way a compiler takes source text, runs a fixed sequence of passes, and emits an artifact you can diff, hash and ship.

Determinism

Same graph → same 12-hex build id → byte-identical artifacts. A diff means what it appears to mean.

Provenance

Every served line carries a [prov:…] ref down to a file and a row. “Where did this come from” is a lookup.

Disagreement is output

The platform’s honest difficulty is a number in census.json, not a thing you find in production.

IdentityL1 · canon/canonical.py

Two expressions that mean the same thing must have the same identity.

One function, nine passes, a pinned order. Everything downstream — equivalence classes, the authority lattice, the census, metric identity — keys on its output.

The pinned order

1 parse            dialect=bigquery
2 strip comments
3 normalize ids    lowercase unquoted
4 qualify columns  full | partial | none
5 de-alias tables  + passthrough-CTE inlining
6 constant fold    literals KEPT
  ↳ fork the template branch here
7 sort commutative operands
8 canonical literals
9 generate         no pretty, fns lowered

No CNF expansion — explosion risk on a 35K-fragment corpus.

Two fingerprints, not one

  • fp_expridentity of the exact expression, literals included — country = 'GB' and 'US' are different filters, and a layer that fuses them lost what users care about most
  • fp_templateliterals → ?s ?n ?d, IN-lists → ?*, forked before sorting, so pattern identity is arity-blind

Rules the corpus taught us

# ruleset 2: COUNT(*) ≡ COUNT(1) — two
# fingerprints for one function is a lie
# the jobs witness exposed: catalog said
# COUNT(1), jobs said COUNT(*), and the
# same metric refused to fuse

x IN ('B') collapses to x = 'B' — found by watching a conflict count that was too high and asking why. The census is not a report, it is an instrument.

Identitycanon/fingerprint.py

Make derived identities carry the version of the deriver.

fp = sha256(canonical_text ⊕ NUL ⊕ dialect ⊕ NUL ⊕ canon_version)[:12]

CANON_VERSION = f"{CANON_RULESET}:{sqlglot.__version__}"

Read that twice: upgrading the SQL parser changes every fingerprint in the system. Which sounds insane, until you price the alternative.

Without the version in the fp

  • An upgrade silently re-fingerprints only the expressions whose canonical form changed.
  • The graph forks identities. Two nodes for one metric.
  • No error. Nobody notices for a month.
  • Recovery: none — you cannot tell which ids drifted.

With the version in the fp

  • Every fingerprint changes. tests/test_canon.py goes red.
  • The remint is a deliberate migration: SAHS_REGEN_GOLDENS=1.
  • Mechanical, because the canonical text is stored beside every fingerprint.
  • Recovery: re-derive every id from stored text.
Silent drift in an identity function is unrecoverable. Loud drift is a Tuesday.the single strongest lesson in the project

Failures are typed, and try_canon never raises

parse_errorfragment dialecttransform out_of_scope — the row's table isn't in this run; nothing is missing not_sql — prose in the SQL column, caught before the parser

One junk row in a 35,700-row corpus must not kill a run. So quarantine is categorized, counted, and the rate becomes a gate. Some rows arrive with label and SQL swapped; detection is deterministic (this side fails to parse, that side parses) and the row is recovered with a flag.

Where an id embeds a source string, the slug happens at exactly one mint site, and the verbatim value stays in props. Real tribal labels carry / . ::; the id is a derivation, not the label.

The storeL2 · graph/quads.py

Provenance is not metadata. It is the payload.

JSONL files in git. That is the entire database. Discipline replaces the database: single writer, append-only, current state is a fold.

On every node and every edge

class Prov(BaseModel):

25 relations, endpoints typed

append_edge refuses an unregistered relation; the validator refuses illegal endpoint kinds. A registry entry is a sentence about the world:

"joins_via":       ({table}, {table})  HOW
"co_queried_with": ({table}, {table})  together
"fk_references":   ({col},   {col})    declared
"certified_as":    ({metric},{status})

Ownership is not usage. The mined business_unit names who runs the queries — a risk team’s patterns sit on a merchant team’s tables. It feeds used_by, never in_lob.

Two traps, paid for once

  • Torn tails. A run killed mid-append leaves a line with no newline. The torn bytes move to a .torn sidecar — evidence, never deleted — and the file truncates to its last complete line.
  • U+2028 / U+2029 / NEL. json.dumps passes them through raw and every line tool, splitlines() included, treats them as breaks. Real catalog descriptions carry them. Escape on write, split on "\n" only on read. If your store is JSONL, this bug is waiting for you.

AggregationL3 · compiler/compile.py

Two guards we would not ship without.

01Max, never sum

ranking = {f: v for f, v in support_by_witness.items()
           if f in RANKING_WITNESSES}
row["support"]           = max(ranking.values(), default=0)
row["witness_agreement"] = len(ranking)
  • The catalog was mined from a superset of the same query history the jobs witness reads. Summing double-counts the same events and rewards overlap.
  • “Strongest single evidence” and “how many independent families” are two questions. A sum smears them together.
  • Max applies within a family too: the same witness corroborating from two directions is one witness, not two.
  • Recency comes from the jobs witness alone — job creation times are the only true timestamps. A fallback is flagged recency_source: "catalog".

02The gold contamination guard

# the gold pairs are the eval answer key — a full
# graph citizen (census, cards, evidence) that
# must never feed a feature the resolver ranks on.
# audit_30d corroborates, never votes.
assert "gold_attested" not in RANKING_WITNESSES
assert "audit_30d"     not in RANKING_WITNESSES

An import-time assertion. The 158 gold prompt→SQL pairs are genuinely useful graph content — they attest expressions, appear as evidence, a steward can read them. They are also the answer key.

The system under test must not contain its own test set. and audit_30d is excluded for a different reason: two witnesses of the same events don’t count twice

If you build a system that both learns from and is evaluated on the same corpus, write this assert. Put it at module import. Let it fail the day somebody adds a family to the wrong tuple.

Identity blocks

Every archive quad’s table must resolve through a human-verified crosswalk (46 signed rows). An unresolvable archive record stops the build — identity confusion is the one error class that corrupts everything downstream.

DENIED is not absence

A denied policy listing becomes has_policy → policy:unknown_denied, and the ACL fails closed. A present-but-empty policy file is confirmed none and emits nothing. Those look identical in a naive loader and mean opposite things.

The agent's worldcompiler/cards.py

Truncation is inevitable. What you truncate is a design decision.

Most systems make that decision accidentally, by ordering. Here it is explicit: the twelfth column can go, the conflict cannot.

The binderL4 · tools/resolver.py

The lattice, made literal as a sort key.

Five tiers, one enum, defined once

CERTIFIED      5   metrics_dmp        ceiling .95
PENDING        4   extended_gmns      ceiling .80
SKILL_CONTRACT 3   packs, gold pairs  ceiling .70
MINED          2   catalog, jobs      ceiling .55
SNIPPET        1   tribal fragments   ceiling .40

The resolver sorts lexicographically on (authority_tier, score_rest):

score_rest = 0.4·log1p(support)/log1p(max_support)
           + 0.3·recency_decay(last_seen, hl 90d)
           + 0.3·context_fit

Because the sort is lexicographic and not a weighted sum, a mined pattern with 6,000 executions loses to a certified KPI with 3, always, by construction. A coefficient is a thing someone tunes. A sort key is not.

Disambiguation is a success state

m < margin_threshold  OR  top reached only via fuzzy
     ⇒ NO BIND — a structured ambiguity with
       named options, each carrying its evidence

Never argmax. An agent that asks “did you mean the certified definition, or the one your team uses?” is doing its job. An agent that picks is gambling with your quarter-end.

Decay is data-relative, not wall-clock

Age is measured against the build’s own newest last_seen. A build re-scored six months later ranks identically. Wall-clock decay would mean the same build answers differently on different days — quietly breaking every reproducibility claim.

Every constant versioned and cited

RESOLVER_CONSTANTS = {"version": "rc1",
  "weights": {support .4, recency .3, context .3},
  "recency_half_life_days": 90,
  "margin_threshold": 0.15,
  "fuzzy_reach_forces_ask": True}

Embedded in every build manifest, cited in every response, and openly labelled uncalibrated bets. A wrong bind is always traceable to the constants that produced it — every slot carries its own features block.

The loopassistant/loop.py

One interaction per turn. The turn ends when the model stops calling tools.

Limits, in code

MAX_CALLS  = 40
WALL_SEC   = 600
RESULT_CAP = 20_000
HISTORY    = 30 msgs

Never a vanished turn

Each limit ends the turn in plain language with what was already said, and a “continue” that resumes the same interaction. Streamed text is never discarded.

One abort path

The stop button and the session breaker share it — so “stop” is exercised by every test that exercises the cap.

Depth, not effort

Quick / Standard / Deep change per-step thinking and nothing else. The call ceiling and the wall clock are identical at every depth.

Contextassistant/loop.py · system_prompt()

Stable parts first, so the prefix caches. The newest ask always last.

Seven sections

  • <identity>a general reasoner first; a thinking question gets thinking, with no tools. Numbers come from tools; reasoning comes from you.
  • <chain>platform governance ≻ the product ≻ this user’s memory and asks ≻ defaults. A remembered preference steers a choice; it never softens a rule.
  • <mode>chat or autopilot — a prompt section, not a gate
  • <graph>SYNAPSE.md, the world digest, ≤2K tokens, generated from the build’s indexes and nothing else
  • <skills>loaded packs whole; the rest of the shelf by name
  • <memory>the project block and what is remembered about this person
  • <session>today’s date, artifacts in this chat, working notes

Then the conversation as messages — instructions after data. Temperature stays at the model default; 0.0 is a documented cause of looping.

The digest is generated, never written

Hand-written prose has no entry point. If a fact is not derivable from the build, it does not appear — the reality law applies to the model’s briefing exactly as it applies to answers.

Deterministic per build, so the assembled prompt is byte-identical across turns. Which is what makes it cacheable.

The date block exists because a model has no clock

# without this line "last month" resolves
# against its training-time sense of now,
# and a window with no upper bound rides

It spells out today, this month, last month, this quarter with its start date, last quarter, year-to-date — and the newest partition the build saw, so “rows after it may not exist yet” is a stated fact rather than a surprise.

It sits in the last section on purpose, so the cached prefix stays stable within a day.

The literal check, in full

for each  column = 'literal'  in the SQL:

  no observed values on record
      → leave it alone. No domain, no opinion.

  literal ∈ observed
      → silent

  literal is a MEANING on record
      → "'KYC done' is the meaning of a stored
         code, not a value: filter with
         status = 'K' (value lookup) and say
         the meaning in the answer"

  otherwise
      → "not among the 8 observed values of
         dw.t.status; closest: 'A', 'D', 'P'
         (the profile estimates 12 distinct values,
         so the list on record is partial)"
  • No domain, no opinion. Silence on columns we know nothing about.
  • A partial list is a hint, not a verdict — if the profiler’s distinct estimate exceeds the observed list, the warning says so.
  • A business phrase gets the code. “Approved” is not a value; 'A' is.
This hook replaced two prose rules. “Read before use” and “sample before filter” left the prompt: the literal hook and the card-shaped tools make the right path the easy path.

Poll-based on purpose

The turn runs in a worker thread (the resolver is CPU work, model calls are blocking HTTP) while SSE consumers live on the event loop. A lock-protected append log that consumers read by sequence number is thread-safe by construction, needs no loop plumbing, and loses nothing on reconnect.

Measurementevals/

Evals are the loss function. Transcripts are the gradient.

Three outcomes, not two

fp ∈ accepted_fps                      → PASS
fp ≠ and (invalid or schema ≠ gold)   → FAIL
fp ≠ and schema matches                → AMBIGUOUS
   counted in neither · its own rate
   · appended to the triage file

Fingerprint equality is a strong and incomplete signal. A different query with the same result schema that dry-runs clean is probably a legitimate alternative phrasing. Scoring it FAIL punishes correct work; scoring it PASS launders wrong work.

Ambiguous items never silently move the floor in either direction. Human triage resolves them — and admitting a fingerprint into a task’s accepted set is how the suite learns.

  • Static result-shape runs before any dry run — no free FAIL should cost a network call.
  • Bytes-scanned is a warning, never a gate — partition pruning makes it flaky, and a flaky gate teaches people to ignore gates.
  • Answering when the task says abstain is its own loud failure class. A confident wrong answer is worse than silence.

pass@1 = mean(c/n)
pass^3 = mean(C(c,3)/C(n,3))   unbiased

deterministic SUTs run n=1;
pass^3 ≡ pass@1 and is never simulated.
0 < c < n on a deterministic SUT is
itself a bug alarm — the harness raises it.

Honest limits

I would rather write this section than have someone else write it for me.

Asserted, not learned

  • The authority lattice. Obviously a certified KPI outranks a wiki fragment. Not obvious that a skill-pack contract outranks a mined pattern with 4,000 executions in every case — and we have no measurement that says it does.
  • The resolver constants. 0.4 / 0.3 / 0.3, a 90-day half-life, a 0.15 margin. Versioned, cited, honestly labelled bets. The ablation could not distinguish them at fixture scale.

Counters that measure less than their names suggest

  • metric_conflicts counts same-identity drift only. Same intent, different formula, different names is invisible to it — and the census meta block says so out loud.
  • Label normalization is case and whitespace only. ALIF and “active locations in force” count separately. Deliberate — better to over-count conflicts than silently merge two meanings — so the total is not a deduplicated count, and the meta says that too.

A census field whose docstring explains what it cannot see is worth more than one that quietly overclaims.

Structural

  • No CNF expansion. Two logically equivalent predicates with different boolean structure will not fuse. Explosion risk on 35K fragments.
  • Single writer, single machine. The store’s correctness rests on “nobody else is appending right now.” That is a discipline, not a lock. It held for a laptop with warehouse access. It would not hold for a team, and the honest fix is a real transaction boundary, not a stricter README.
  • The loaders are shaped to specific exports. Nine documented layouts. Pointing this at another warehouse is real work, and the README says so rather than implying a pip install will do it.

The enrichment gate optimises against its own exam

The prompt history is the most instructive document in the tree: b1.1 halted at 56% (and its grader passed a Card-Present / Card-Not-Present swap in both directions — so a negation veto was added, and graders may only tighten from there). b1.2 halted at 59%. b1.3 opened the gate at 62%, tier item review.

A context probe on b1.3’s misses found that two of the three problems were ours: five cases were unwinnable from the context shown, and the vocab shelf was feeding poison (SQL keywords and two-letter column fragments matching unrelated acronyms).

Almost none of the engineering that made this work was about the model.

It was about making the environment truthful enough that intelligence had something to stand on.

Ten things to steal, in order of what they earned

  1. Embed the deriver’s version in every derived identity.
  2. Fold at witness granularity; aggregate at read time.
  3. Max, not sum, when sources overlap — then report agreement separately.
  4. Make the ranking a lexicographic sort on a governance tier, not a weighted feature. Nobody can tune governance away.
  5. Assert your evaluation set out of your ranking features at import time.
  6. DENIED is not absence. Give unknowns their own node and fail closed.
  7. Categorize your quarantine and gate on the rate.
  8. Ledger every input file as consumed / deferred(reason) / inventoried.
  9. Truncate on purpose, with a named drop order and a never-drop list.
  10. Make errors say what to do. “The store is derivable: remove these two directories and re-run” beats a stack trace every time.

The principle underneath all of it

Make the environment truthful before making the model clever. Intelligence on a lying environment is confident nonsense; intelligence on a truthful one compounds.docs/harness-discipline.md · principle 8
