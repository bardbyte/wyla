# Industry Landscape: Semantic Layers and the Interfaces Built on Them (2025–2026)

**Status:** research report, compiled 2026-07-07. Companion to `docs/SEMANTIC_LAYER_BLUEPRINT.md`.
**Method:** deep-research fan-out (six parallel research passes over the four rings) + adversarial verification of load-bearing claims (accuracy numbers, GA dates, M&A) against primary sources — vendor docs, launch posts, engineering blogs, GitHub READMEs/changelogs, press releases, arXiv. Several vendor domains block automated fetching, so some exact wording is sourced via search-index copies of the cited primary pages, cross-checked against a second source. Every substantive claim carries a link; accuracy figures are flagged vendor-reported unless independently published.

## Executive Summary

**The five defining industry patterns of 2025–2026:**

1. **Semantic grounding is sold with an accuracy delta.** Every serious vendor justifies its semantic layer with a "with vs. without" NL→SQL benchmark: Snowflake reports Cortex Analyst at "90%+ accuracy on real-world use cases… close to 2x more accurate than single-shot SQL generation using a state-of-the-art LLM, like GPT-4o" ([launch post](https://www.snowflake.com/en/blog/cortex-analyst-ai-self-service-analytics/), with GPT-4o at ~51% on their internal BI eval per the [methodology blog](https://www.snowflake.com/en/blog/engineering/cortex-analyst-text-to-sql-accuracy-bi/)); AtScale reports 92.5% vs. ~20% on TPC-DS — and 0%→70% on high-complexity questions ([Businesswire](https://www.businesswire.com/news/home/20240808651958/en/AtScale-Unveils-Breakthrough-in-Natural-Language-Processing-with-Semantic-Layer-and-Generative-AI)); data.world's peer-reviewed benchmark shows 16.7%→54.2% overall and **0%→~36-39% on high-schema-complexity questions** with a knowledge graph ([arXiv:2311.07509](https://arxiv.org/abs/2311.07509)); dbt's own benchmark: raw text-to-SQL improved from 32.7% (GPT-4, 2023) to only 64.5% (frontier models, 2026) while semantic-layer-mediated queries hit 100% of in-scope questions ([dbt](https://docs.getdbt.com/blog/semantic-layer-vs-text-to-sql-2026)); an independent(ish, Cube-affiliated) 2026 paired benchmark shows +17–23pp across three frontier models ([arXiv:2604.25149](https://arxiv.org/abs/2604.25149)). "Trusted data + LLM" is the universal pitch: the semantic layer is now marketed primarily as *the thing that makes AI not lie*.
2. **The verified-answer escrow is THE trust mechanism.** The convergent answer to "why trust the bot" is a human-blessed question→query repository surfaced as a binary badge: Snowflake's Verified Query Repository — now an `AI_VERIFIED_QUERIES` DDL clause with `verified_by`/`verified_at` ([docs](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst/verified-query-repository)), Databricks Genie's Trusted Assets ("the response is automatically labeled as Trusted," [docs](https://docs.databricks.com/en/genie/trusted-assets.html)), Power BI's Verified Answers with trigger phrases and a verified checkmark ([Microsoft Learn](https://learn.microsoft.com/en-us/power-bi/create-reports/copilot-prepare-data-ai-verified-answers)), Amazon Q's verified-answers tab ([AWS](https://docs.aws.amazon.com/quicksight/latest/user/quicksight-q-topics.html)), ThoughtSpot's Coach Spotter reference answers ([docs](https://docs.thoughtspot.com/cloud/latest/spotter-coach)), Lightdash's verified answers + evaluations ([docs](https://docs.lightdash.com/guides/ai-agents)). Trust is asset/query-level and binary — verified or not — never per-fact, never calibrated.
3. **MCP-ification of the whole stack.** Between April 2025 (dbt MCP server, [launch](https://docs.getdbt.com/blog/introducing-dbt-mcp-server)) and mid-2026, effectively every semantic layer, warehouse, catalog, and BI tool shipped an MCP server: Snowflake managed MCP as a first-class database object (`CREATE MCP SERVER`, GA [Nov 4, 2025](https://docs.snowflake.com/en/release-notes/2025/other/2025-11-04-cortex-agents-mcp)), Databricks managed MCP with on-behalf-of auth ([blog](https://www.databricks.com/blog/announcing-managed-mcp-servers-unity-catalog-and-mosaic-ai-integration)), Cube, Honeydew, Wren Engine, Malloy Publisher, Omni, ThoughtSpot Spotter, Looker, Atlan, Alation, Collibra, Select Star, Secoda, OpenMetadata, DataHub. Agent governance = identity pass-through + per-tool grants + post-hoc audit logs — **not** pre-execution human approval.
4. **The "context layer" land-grab and the consolidation wave.** Metadata vendors rebranded as context (Atlan "The Context Layer for AI", DataHub "The Context Platform", OpenMetadata "The Open Context Layer", Databricks "Genie Ontology… context layer"), and the platforms bought the category inside 14 months: data.world→ServiceNow (May 7, 2025), Numbers Station→Alation (May 20, 2025), Metaphor→KPMG (Apr 28, 2025), Seek AI→IBM (June 2, 2025), Select Star→Snowflake (Nov 24, 2025), Secoda→Atlassian, plus the dbt+Fivetran merger (announced Oct 13, 2025; closed June 1, 2026) pitched as "the data infrastructure for trusted AI agents" and shipping an open **"Agents Schema"** standard ([Fivetran press](https://www.fivetran.com/press/fivetran-dbt-labs-complete-merger-to-create-the-data-infrastructure-for-trusted-ai-agents)). Interop is standardizing through the **Open Semantic Interchange** (announced Sept 23, 2025; spec v1.0 published Apache-2 on Jan 27, 2026; MetricFlow relicensed Apache-2 as reference implementation) ([Snowflake press](https://www.snowflake.com/en/news/press-releases/snowflake-salesforce-dbt-labs-and-more-revolutionize-data-readiness-for-ai-with-open-semantic-interchange-initiative/), [spec finalized](https://www.snowflake.com/en/blog/open-semantic-interchanges-specs-finalized/), [OSI repo](https://github.com/open-semantic-interchange/OSI)).
5. **Semantics are moving into the database, and the layer is learning itself.** Definitions are becoming warehouse-native governed objects — Snowflake `CREATE SEMANTIC VIEW` (GA Summit June 2025; standard-SQL querying GA Mar 2, 2026, [docs](https://docs.snowflake.com/en/user-guide/views-semantic/overview)), Databricks Unity Catalog metric views (`MEASURE()`, GA Apr 2, 2026, with the core open-sourced into Apache Spark, [blog](https://www.databricks.com/blog/redefining-semantics-data-layer-future-bi-and-ai)) — inheriting warehouse RBAC for free. And the authoring bottleneck is under attack from self-building semantics: Snowflake **Semantic View Autopilot** (GA Feb 3, 2026 — builds *and maintains* semantic views from usage, auto-surfacing candidate verified queries for human review, [press](https://www.snowflake.com/en/news/press-releases/snowflake-delivers-semantic-view-autopilot-as-the-foundation-for-trusted-scalable-enterprise-ready-AI/)), Databricks **Genie Ontology** (June 16, 2026, preview) — "a continuously learned graph" that weighs a definition's source, author authority, usage, certified-asset proximity, and freshness, "PageRank-like" ([blog](https://www.databricks.com/blog/introducing-genie-one-genie-ontology-and-genie-agents)), Zenlytic Zoë Self-Learning (May 13, 2026), Cube D3's AI Data Engineer (June 2, 2025), ThoughtSpot SpotterModel.

**Our three sharpest differentiators (Synapse/Radix vs. the field):**

1. **Per-fact provenance with calibrated confidence tiers.** Nobody ships answer-level, per-fact evidence — multiple independent sources + a calibrated tier (grounded/inferred/guessed → Corroborated/Sourced/Reported/Inferred chips) with witness panels and conflict surfacing. The market's ceiling: binary badges (verified/trusted/certified), citation links to definitions (Zenlytic Citations), and one machine-readable but single-signal field (Cortex Analyst's REST `confidence.verified_query_used`). Genie Ontology *fuses* multi-source authority internally but never exposes it as user-facing evidence. No product distinguishes "three independent systems agree" from "one LLM guess."
2. **Gated warehouse execution with hold-to-approve and an audit ledger.** Every commercial AI analyst auto-executes reads and explains *afterwards*. The approval seam exists only at API level (Cortex Analyst returns SQL without executing it; Genie's Conversation API separates generation from `executemessageattachmentquery`) and at curation time (verified queries, Seek AI's analyst-review queue) — never as product UX. A 5-gate machine chain (read-only shape → guardrail check → dry-run → byte/cost budget → row cap) + human sign-off + per-attempt ledger exists nowhere as product.
3. **The Brief: durable, claim-structured answer artifacts pinned to a content-addressed graph snapshot.** Industry output is a chat transcript, notebook, or dashboard. Closest neighbors: Hex ("all the work you do with the agent becomes a durable, debuggable asset," [Hex](https://hex.tech/blog/introducing-notebook-agent/)) and Julius's stamp-to-notebook reproducibility ([docs](https://julius.ai/docs/notebooks/reproducibility-in-notebooks)); the gap is even acknowledged in research ([arXiv:2605.12087](https://arxiv.org/abs/2605.12087) on durable intermediate artifacts vs. chat transcripts). No one structures answers as claims-with-evidence, and no one pins answers to a reproducible context snapshot version.

**Our three biggest table-stakes gaps:**

1. **No verified-query escrow loop.** The single most standardized trust feature in the market (VQR / Trusted Assets / Verified Answers / reference answers) is missing from our stack: stewards can't promote a validated Q→SQL pair into a repository that grounds retrieval and stamps future answers "verified." Our human-approval witness (weight 10) is the natural backend for exactly this.
2. **No metric compilation/execution surface or interchange format.** MetricFlow, Cube, AtScale, semantic views all compile and execute metric queries and serve JDBC/SQL/REST to BI tools; we emit validated SQL but have no `query_metric()` execution path, no BI-tool consumption, and no OSI import/export — which (with dbt/Fivetran's Agents Schema) is fast becoming the interop lingua franca.
3. **No bootstrap/continuous-learning automation and no in-surface feedback capture.** The market auto-builds semantic models (Semantic View Autopilot, SpotterModel, Zoë Self-Learning, Cube AI Data Engineer), turns thumbs-down into instructions/verified examples (Genie "Ask for review," Coach Spotter, Lightdash agents that "remember corrections"), and ships in-product eval sets (Genie benchmarks, up to 500 curated Q→SQL tests; Lightdash evaluations built from real threads; Cortex Analyst evaluation harness). Our graph compiles on trigger, has no usage-driven refresh, no correction-capture UX, and the golden-set harness is spec'd but not shipped. Adjacent assumed table stakes: on-behalf-of user identity into the warehouse (we run one SVC ID) and a Slack/Teams surface.

**Single best interface idea to steal:** Snowflake's **verified-query promotion loop** — human-verified Q→SQL pairs stored in the semantic model ground retrieval; on exact match the verified SQL is returned directly and the answer is flagged; the API exposes `verified_query_used` provenance; Snowsight offers a one-click "save as verified query" after a correct answer; and Semantic View Autopilot now auto-mines candidate verified queries from live usage *for steward review* ([VQR docs](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst/verified-query-repository), [suggestions](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst/verified-query-suggestions), [Autopilot](https://www.snowflake.com/en/blog/semantic-view-autopilot/)). Grafted onto our Brief: "Promote this claim's SQL to verified" writes a `human_approval` fact (weight 10) and upgrades the evidence chip — closing the loop our SOURCE_WEIGHTS already prices.

## Ring 1 — Semantic Layer Platforms

### dbt Semantic Layer + MetricFlow (dbt Labs → Fivetran+dbt)

- **What it is:** semantic models + metrics as **version-controlled YAML in the dbt project**; MetricFlow (acquired with Transform, Feb 2023) compiles metric requests into optimized, warehouse-dialect SQL; the hosted layer stores no data ([docs](https://docs.getdbt.com/docs/use-dbt-semantic-layer/dbt-sl), [MetricFlow](https://github.com/dbt-labs/metricflow)).
- **Authoring/governance:** the archetype of code-governed definitions — git, PR review, CI, environments. 2025 spec modernization removed `measures` as a separate authoring concept and made "simple metrics" the primary building block, with inline semantic annotations; shipped first on the Rust-based **dbt Fusion engine** (launched May 28, 2025, from the SDF acquisition) ([spec blog](https://docs.getdbt.com/blog/modernizing-the-semantic-layer-spec), [Fusion](https://www.getdbt.com/blog/dbt-labs-redefines-dbt-with-new-fusion-engine)).
- **Interfaces:** humans — YAML in IDE (dbt Studio, VS Code extension) + MetricFlow CLI; consumers — **JDBC (Arrow Flight SQL), GraphQL, Python SDK**, and first-party integrations: Tableau, Google Sheets, Excel, Hex, Mode, Klipfolio, Lightdash, Push.ai ([APIs](https://docs.getdbt.com/docs/dbt-cloud-apis/sl-api-overview), [integrations](https://docs.getdbt.com/docs/cloud-integrations/avail-sl-integrations)). Durable-artifact primitives: **saved queries** and **exports** (scheduled materialization of governed queries) ([docs](https://docs.getdbt.com/docs/build/saved-queries)). Trust-signal primitives: dbt Explorer **data health signals** and embeddable **data health tiles** in downstream dashboards ([docs](https://docs.getdbt.com/docs/explore/data-health-signals)).
- **License/standards arc:** MetricFlow went AGPL → BSL 1.1 → **Apache 2.0 at v0.209.0 (Oct 2025)**, contributed as the OSI reference implementation, with OSI-format converters landing spring 2026 ([changelog](https://github.com/dbt-labs/metricflow/blob/main/CHANGELOG.md), [press](https://www.prnewswire.com/news-releases/dbt-labs-affirms-commitment-to-open-semantic-interchange-by-open-sourcing-metricflow-302582866.html)).
- **AI story:** dbt MCP server (Apr 21, 2025, [launch](https://docs.getdbt.com/blog/introducing-dbt-mcp-server)); remote MCP GA with OAuth + **dbt Agents** at Coalesce (Oct 2025) ([blog](https://www.getdbt.com/blog/dbt-agents-remote-dbt-mcp-server-trusted-ai-for-analytics)); an "Analyst agent" inside dbt Insights ([release notes](https://docs.getdbt.com/docs/dbt-versions/2025-release-notes)); its own public benchmark repo (dbt-llm-sl-bench) showing text-to-SQL at 32.7% (2023) → 64.5% (2026) vs. 100% for in-scope semantic-layer queries ([post](https://docs.getdbt.com/blog/semantic-layer-vs-text-to-sql-2026)).
- **Corporate arc:** merger with Fivetran announced Oct 13, 2025 (~$600M combined ARR), completed June 1, 2026 as "the data infrastructure for trusted AI agents"; dbt's framing: "Agents don't bring context; they inherit it" ([dbt](https://www.getdbt.com/blog/fivetran-and-dbt-are-one-company-now-here-s-what-that-means), [press](https://www.businesswire.com/news/home/20260601514374/en/Fivetran-dbt-Labs-Complete-Merger-to-Create-the-Data-Infrastructure-for-Trusted-AI-Agents)). Launched **Agents Schema** — an open standard designating a warehouse schema as the shared agent-context layer (metric definitions, semantic models, lineage, docs as plain SQL tables).
- **Adoption reality check:** dbt's 2025 State of Analytics Engineering (459 respondents): ~30% use AI to consume data via NL; of those, **two-thirds do vanilla SQL generation vs. one-third through a semantic layer**; 27% plan increased SL investment ([summary](https://www.getdbt.com/blog/state-of-analytics-engineering-2025-summary)). The grounding gospel runs ahead of practice.

### Cube (Cube Core / Cube Cloud / D3)

- **What it is:** open-source (Apache-2) headless semantic layer — metrics, dimensions, joins, access rules defined once in **YAML/JS/Python** (`cubes` + governed `views`), with pre-aggregations for latency; May 14, 2026 formalized the split: Cube Core stays OSS (with an LTS program), "Cube" is the commercial agentic-analytics platform ([GitHub](https://github.com/cube-js/cube), [Core-and-Cube post](https://cube.dev/blog/cube-core-and-cube)).
- **Interfaces:** the widest fan-out in the category — REST, GraphQL, **SQL API on the Postgres wire protocol**, **MDX API (Excel)** and **DAX API (Power BI)**, an AI API (turnkey NL→semantic-query endpoint, GA Dec 2024), a Chat API for embedded agents (including **agent-to-agent access via MCP**), and a hosted OAuth MCP server ([APIs](https://cube.dev/docs/product/apis-integrations/sql-api), [AI API](https://cube.dev/blog/introducing-the-ai-api-and-chart-prototyping-in-cube-cloud), [embedded agentic analytics](https://cube.dev/blog/announcing-embedded-agentic-analytics), [MCP docs](https://docs.cube.dev/docs/integrations/mcp-server)).
- **D3 (June 2, 2025):** "the first agentic analytics platform built on a universal semantic layer" — an **AI Data Analyst** (NL → semantic SQL, charts, interactive data apps) and an **AI Data Engineer** (auto-builds/optimizes models) ([PR](https://www.prnewswire.com/news-releases/cube-launches-d3-the-first-agentic-analytics-platform-built-on-a-universal-semantic-layer-302469860.html), [blog](https://cube.dev/blog/unleashing-agentic-analytics-with-cube-d3)). Trust UX: "explainable, auditable results with full lineage, access control, and certified queries"; "it shows you how it got there — the semantic SQL query, metric definition" ([DBTA](https://www.dbta.com/Editorial/News-Flashes/Cubes-D3-Platform-Reimagines-Analytics-with-an-AI-Agent-Native-Framework-169786.aspx)). D3 "spaces" carry **rules governing agent behavior** ("always rules" / "agent-requested rules") — a nascent policy-gate pattern. Execution is automatic; explanation is post-hoc.
- **Signals:** $25M round led by Databricks Ventures (2024); CEO Artyom Keydunov's 2023 essay predates the wave: LLMs "need a semantic layer" for "context and constraint… a solution for the LLM hallucination problem" ([essay](https://cube.dev/blog/semantic-layer-the-backbone-of-ai-powered-data-experiences)).

### AtScale

- **What it is:** enterprise universal semantic layer with an OLAP heritage — virtual multidimensional cubes over cloud warehouses, autonomous aggregate management, and pushdown; its moat is serving **live Excel (XMLA/MDX) and Power BI (DAX)** plus Tableau/JDBC off one model ([product](https://www.atscale.com/use-cases/universal-semantic-layer/)).
- **Authoring:** dual-mode — Design Center GUI *and* **SML (Semantic Modeling Language)**: YAML, object-oriented, stored in customer git repos with branch/PR workflows; **open-sourced Apache-2 Sept 2024** (spec v1.6 by 2026) with converters to/from Snowflake Cortex semantic models, Databricks UC metrics, and Power BI ([press](https://www.atscale.com/press/atscale-announces-the-open-source-release-of-semantic-modeling-language/), [GitHub](https://github.com/semanticdatalayer/SML)).
- **AI story:** the loudest benchmark marketer — TPC-DS NL2SQL study (Aug 2024): **92.5% with the semantic layer vs. ~20% schema-only GPT-4, and 0% → 70% on high-complexity questions**, followed by an open text-to-SQL leaderboard ([BigDataWire](https://www.hpcwire.com/bigdatawire/2024/08/15/atscale-claims-text-to-sql-breakthrough-with-semantic-layer/), [leaderboard](https://www.atscale.com/press/first-public-leaderboard-text-to-sql/), [benchmark repo](https://github.com/NLQBenchmarks/TPCDS_Benchmark)). Joined OSI Jan 27, 2026. Sharpest 2026 move: **"Snowflake Semantic Views XMLA Endpoint, powered by AtScale"** — a Snowflake Native App exposing native semantic views to Excel/Power BI over live XMLA (June 2, 2026, [press](https://www.businesswire.com/news/home/20260602266545/en/)) — the independent layer surviving by becoming the legacy-protocol head on warehouse-native semantics.

### Looker / LookML (Google Cloud)

- **What it is:** the archetypal governed BI semantic layer — LookML (models/explores/views/dimensions/measures) in git, compiled to SQL at query time ([docs](https://docs.cloud.google.com/looker/docs/what-is-lookml)).
- **Authoring/governance:** the strongest model-change approval gates in the category: dev/prod modes, per-developer branches, an admin-enforceable **"Pull Requests Required"** setting, LookML validator + Content Validator (does this change break saved dashboards?) ([docs](https://docs.cloud.google.com/looker/docs/version-control-and-deploying-changes)). Note: gates are on *model changes*, never on query execution.
- **Interfaces:** Looker UI; **Open SQL Interface** — LookML models over JDBC (Avatica) powering official Tableau and ThoughtSpot connectors ([docs](https://docs.cloud.google.com/looker/docs/sql-interface)); **Conversational Analytics API** (GA) as the programmatic agentic backend; a **Looker-managed MCP server** (preview) with admin-curated tool exposure; Next '26 added a VS Code LookML AI agent and native reads of BigQuery metric definitions and Snowflake semantic views ([Next '26 blog](https://cloud.google.com/blog/products/business-intelligence/looker-updates-for-agentic-bi-at-next26)). PayPal scaled conversational analytics to 3,000+ users via Claude Desktop + Looker MCP (same post).
- **Cautionary tale:** **Looker Modeler**, the 2023 plan to sell LookML as a standalone metrics layer, never reached GA and was quietly shelved; the strategy survived as the Open SQL Interface + connectors + MCP ([announcement](https://cloud.google.com/blog/products/data-analytics/introducing-looker-modeler), [retrospective](https://blog.dataengineerthings.org/how-the-long-established-bi-tool-looker-survives-the-ai-era-8ddf454a7ffc)). Standalone semantic layers don't sell; grounding layers for AI do.

### Malloy (+ Publisher)

- Open-source **semantic modeling + query language** (source→relationships/dimensions/measures once; nested results) by Lloyd Tabb, LookML's inventor — who left Google for Meta in May 2024 explicitly to advance Malloy ([announcement](https://x.com/lloydtabb/status/1786784460702376077)); 2026 talks describe Malloy as transferred to the **Linux Foundation** ([talk listing](https://aicouncil.com/talks26/malloy-an-experimental-language-for-data)).
- Interfaces: VS Code extension + malloy-composer for humans; **Malloy Publisher** — "the open-source semantic model server" — serves models over **REST + two MCP servers**, including an agent-specific one exposing `malloy_getContext` (plain-English question → relevant model entities) and bundled agent "skills" as MCP prompts ([GitHub](https://github.com/malloydata/publisher)). Candor note: Publisher's MCP endpoints are "stateless and unauthenticated — run behind your own gateway" — i.e., zero built-in agent governance.
- LLM pitch: composing from a governed menu of first-class analytical objects "minimizes… hallucinations" ([malloydata.dev](https://www.malloydata.dev/), [Carlin Eng](https://carlineng.com/?postid=malloy-intro)).

### Boring Semantic Layer (BSL)

- Deliberately minimal MIT-licensed Python semantic layer **on Ibis** (joint xorq-labs + Boring Data/Julien Hurault): semantic tables wrap Ibis expressions, so one model compiles to DuckDB/Snowflake/BigQuery; first PyPI release June 24, 2025, 33 releases by June 2026; v2 made semantic tables fully composable Ibis expressions ([GitHub](https://github.com/boringdata/boring-semantic-layer), [launch](https://juhache.substack.com/p/the-boring-semantic-layer), [v2](https://juhache.substack.com/p/boring-semantic-layer-v2)).
- **MCP-first by design**: agents get `list_metrics()`/`get_dimension_values()` and submit a constrained JSON query format — "the LLM shifts from 'SQL writer' to 'Semantic Query Writer'" ([BSL+MCP](https://juhache.substack.com/p/boring-semantic-layer-mcp)); dltHub demonstrated LLM-autogenerated BSL models ([dlt blog](https://dlthub.com/blog/building-semantic-models-with-llms-and-dlt)). Signal: a credible semantic-tool-surface for agents is now a pip install — the moat is not the query compiler.

### Honeydew

- Snowflake-native semantic layer startup (Snowflake Ventures investment; Native App in Snowsight so all compute stays in the customer warehouse) ([investment blog](https://www.snowflake.com/en/blog/investment-honeydew-business-intelligence/), [native app rationale](https://honeydew.ai/uncategorized/why-did-we-build-a-native-app-for-honeydew-semantic-layer-on-snowflake/)). Verified: **not acquired** as of July 2026 (rumors of a ThoughtSpot acquisition are false; both are independent OSI founding members).
- **Authoring/governance — the clearest human-approval-gate pattern in Ring 1:** every semantic object is a YAML file in git with an owner; changes flow through review-and-approve before merging to the shared layer; editable as code (engineers), web UI (analysts), or API ([MCP docs](https://honeydew.ai/docs/integration/mcp)).
- Interfaces: Tableau/Power BI/Looker (generates LookML)/Excel; bidirectional interop with Snowflake semantic views (import + extend, serve Cortex Analyst models) ([blog](https://honeydew.ai/blog/honeydew-and-snowflake-semantic-views/)); an MCP server where agents explore models, edit them conversationally, and query — "Honeydew compiles every MCP request into explainable steps and optimized SQL, preventing hallucinated joins, invalid filters, or mismatched metrics" ([docs](https://honeydew.ai/docs/integration/mcp)). Claims ~100% correctness on covered questions and >95% accuracy at >10,000 business objects (vendor, [blog](https://honeydew.ai/blog/talk-to-your-data-loudly/)).

### Snowflake Semantic Views

- **What it is:** semantics as a **schema-level database object** — `CREATE SEMANTIC VIEW` with TABLES / RELATIONSHIPS / FACTS / DIMENSIONS / METRICS blocks, synonyms, comments, and an **`AI_VERIFIED_QUERIES` clause** (question, SQL, verified_at, verified_by) baked into the DDL ([docs](https://docs.snowflake.com/en/user-guide/views-semantic/overview), [DDL](https://docs.snowflake.com/en/sql-reference/sql/create-semantic-view)). Timeline: preview Apr 17, 2025 → GA at Summit June 2025 → `SEMANTIC_VIEW()` query construct GA Aug 2025 → **standard-SQL querying GA Mar 2, 2026** ([release note](https://docs.snowflake.com/en/release-notes/2026/other/2026-03-02-semantic-views-standard-sql)).
- **Authoring:** SQL DDL, Snowsight wizard/object explorer, a YAML interchange spec, and a `dbt_semantic_view` materialization package (semantic views as version-controlled dbt models) ([package](https://github.com/Snowflake-Labs/dbt_semantic_view)).
- **Consumers:** Sigma (native integration), Hex Semantic Model Sync, Omni (can write DDL back), ThoughtSpot (auto-ingests into Spotter context) ([ThoughtSpot blog](https://www.thoughtspot.com/blog/snowflake-semantic-views-thoughtspot-one-ai-context-layer)); grounding primitive for Cortex Analyst/Agents and Snowflake Intelligence; inherits RBAC/masking/row policies natively.
- **Semantic View Autopilot** (GA Feb 3, 2026): agentic service that auto-builds, optimizes, and *maintains* semantic views by learning from query history and BI assets, "automatically surfaces new verified queries for review"; drift maintenance spans dbt, Looker, Sigma, ThoughtSpot consumers ([press](https://www.snowflake.com/en/news/press-releases/snowflake-delivers-semantic-view-autopilot-as-the-foundation-for-trusted-scalable-enterprise-ready-AI/), [blog](https://www.snowflake.com/en/blog/semantic-view-autopilot/)).

### Databricks Unity Catalog Metric Views

All three collapse the standalone metrics layer into platforms — the Looker Modeler shelving and the Benn Stancil "economic failure" post-mortem (below) explain why the survivors all attached themselves to either a BI surface or an agent story.

### Governance when the consumer is an agent

- **Identity & on-behalf-of auth:** Databricks OBO token passing — "Agents inherit the invoking user's data permissions in real time… If you can't access a table in Unity Catalog, neither can the agent acting on your behalf," extended through Unity AI Gateway to external MCP calls ([UC agent governance](https://www.databricks.com/blog/governing-ai-agents-scale-unity-catalog), [AI Gateway governance](https://www.databricks.com/blog/ai-gateway-governance-layer-agentic-ai)); Snowflake agents execute under the calling user's role with least-privilege programmatic access tokens ([docs](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-agents)).
- **Gateway controls:** Databricks **Mosaic/Unity AI Gateway** — rate limits in **queries-per-minute and tokens-per-minute per endpoint/user/group/service principal**, guardrails (PII detection/blocking, safety/keyword/topic filters), **payload logging of full requests/responses to Delta inference tables** for "rigorous regulatory audits" (doubling as eval corpora), and "unified agent tracing across model and MCP activity" analyzable in Lakewatch ([docs](https://docs.databricks.com/aws/en/ai-gateway/)); Budget Policies for agent cost attribution.
- **Audit:** Snowflake's immutable `AI_OBSERVABILITY_EVENTS` + `CORTEX_ANALYST_REQUESTS_V`; Databricks UC audit logs record principal, agent, MCP connection name, and the OBO flag per request; Genie Monitoring tab; Secoda "all interactions logged."
- **MCP protocol security:** the **June 18, 2025 spec update** made MCP servers OAuth Resource Servers with RFC 8707 audience-bound tokens and added **elicitation** (server-initiated mid-run confirmation requests); the spec's principles say "there should always be a human in the loop with the ability to deny tool invocations" but "cannot enforce these security principles at the protocol level" ([Auth0 analysis](https://auth0.com/blog/mcp-specs-update-all-about-auth/), [spec](https://modelcontextprotocol.io/specification/draft/basic/authorization)). Prompt injection is the live threat: the mid-2025 **Supabase MCP/Cursor incident** (agent with service-role access processed a support ticket containing embedded SQL instructions and exfiltrated tokens) is the canonical case ([writeup](https://www.mintmcp.com/blog/prevention-detection-ai-agents)); Anthropic's own docs warn "servers that fetch external content can expose you to prompt injection risk."
- **The human-sign-off void (verified negative finding):** no data vendor ships an approval inbox where a human signs off each agent-initiated warehouse query before execution. The market's substitutes: (a) **pre-approval of templates** (VQR, Trusted Assets, verified answers — approval of *definitions*, not *executions*); (b) **per-call client-side prompts** (Claude's tool permissioning; `requiresUserInteraction` metadata); (c) **framework middlewares** (LangChain human-in-the-loop approve/edit/reject of a proposed SQL call, OpenAI Agents SDK, Microsoft Agent Framework, Cloudflare Agents); (d) API seams (Cortex Analyst and Genie return SQL separately from execution). Practitioner commentary names the gap: "with agentic systems the human-in-the-loop disappears entirely… Governance before execution is now dealing with consequences after something breaks" ([Readyset](https://readyset.io/blog/ai-generated-sql-database-governance)); DIY checkpoint patterns circulate as blog architecture ([TDS](https://towardsdatascience.com/a-multi-agent-sql-assistant-you-can-trust-with-human-in-loop-checkpoint-llm-cost-control/)).

### 2. Divergences and white space (the five specific checks)

1. **Per-fact provenance with calibrated confidence tiers — WHITE SPACE.** The market's maximum: binary badges (verified/trusted/certified); citation links to definitions (Zenlytic) or grounding content (Power BI); colored object flags at authoring time (Alation TrustCheck); and exactly one machine-readable per-answer provenance field (Cortex Analyst's `confidence.verified_query_used`). "No vendor exposes numeric confidence in end-user UX" held across all six research passes. Nobody attaches to each fact the set of independent sources supporting it, a calibrated tier, or conflict annotations. Genie Ontology computes source-authority weights and hides them in ranking.
2. **Multi-source evidence fusion with explicit weights — EMERGING, OPAQUE.** Genie Ontology (June 2026, preview) is the first shipping fusion engine (source origin × author authority × usage × certified-asset proximity × freshness); TextQL's Ontology indexes warehouses+dbt+Looker+catalogs+docs into one reasoning layer; Alation BAE, Select Star popularity, and DataHub's `get_dataset_queries` all mine **query logs** as agent context; Metaphor treated Slack threads as metadata. But none fuse profiling + query-corpus + curated expert knowledge + gated LLM enrichment as *distinct, provenance-tracked evidence classes with declared trust priors*, none recompute a per-fact tier on every touch, and none expose the fusion for audit (`explain_confidence` has no market equivalent). Expect fast-follow from Databricks/Snowflake; *transparency of fusion* is the defensible part, not fusion itself.
3. **Human-in-the-loop signing for agent-initiated warehouse queries + audit ledger — WHITE SPACE (verified negative).** Universal behavior: reads auto-execute under RBAC; audit is post-hoc (AI Gateway payload logging, immutable observability event tables, Genie monitoring). Approval exists at four seams, none productized as execution UX: curation-time template approval (VQR/Trusted Assets; Seek AI's analyst-review queue is the archetype), generic MCP client tool prompts + spec elicitation, agent-framework middlewares (LangChain/OpenAI/Microsoft/Cloudflare approve-edit-reject), and the raw API seams (Cortex Analyst and Genie both return SQL separately from execution). Nobody ships pre-execution machine gates (dry-run cost estimate → budget → guardrail) surfaced to a human as hold-to-approve with a signed per-attempt ledger. For regulated buyers this is the difference between deployable and not — and it is exactly what commentators say is missing ([Readyset](https://readyset.io/blog/ai-generated-sql-database-governance)).
4. **Durable answer artifacts vs. chat transcripts — MOSTLY WHITE SPACE.** Partial versions: Hex agent-work-as-notebook ("durable, debuggable asset"), Julius stamp-to-deterministic-notebook, Genie/Quick Suite/Snowflake cited deep-research reports, ThoughtSpot createLiveboard-from-chat, Cube D3 data apps, dbt saved queries/exports, pinned answers in Snowflake Intelligence. The gap is now named in research ([arXiv:2605.12087](https://arxiv.org/abs/2605.12087): agent systems need "typed, structured, addressable, versioned" artifacts "distinguished from chat transcripts"). Nobody structures answers as **claims with per-claim evidence and tier**, and nobody pins an answer to a content-addressed context snapshot for reproducibility.
5. **Machine-enforced policy refusals as UX — THIN / WHITE SPACE.** What exists: refusal-as-abstention (Cortex Agents "answer abstaining"; Cortex Analyst's classifier rejects ambiguous/non-SQL questions with suggestions), refusal-as-clarification (Genie's scripted clarifying questions; Wren's "Clarification needed"), silent narrowing (RLS/masking pass-through — out-of-permission data is simply invisible), gateway filters (PII/topic/keyword blocking in AI Gateway), and scope constraints (BSL/dbt metric menus; Cube D3 space rules; admin-curated MCP tools in Looker). What does not exist: a refusal that **names the violated rule, cites the rule's provenance, and proposes the compliant alternative** ("guardrail G-12 forbids LAG() over roll_rate_calc — here's the approved pattern"). Refusal-with-cited-reason is an unclaimed trust surface.

### 3. Positioning read for Synapse/Radix

**Where we genuinely differentiate:**

- **Provenance-typed knowledge graph with calibrated tiers, exposed.** Five-witness fusion (MDM, BQ profiling, gold-SQL corpus, curated skills, gated LLM) with declared `SOURCE_WEIGHTS`, per-fact `Provenance` envelopes, tier recomputation on every touch, and `explain_confidence` as a first-class tool is ahead of Genie Ontology on *transparency* (they weight; we weight **and show**) and ahead of everyone on the corroboration principle (distinct-source breadth > single-source depth). The industry's own benchmark discourse validates the thesis; its own consolidation wave (four catalogs bought for their context) validates the asset. The witness-panel/evidence-chip UX has no competitor.
- **The 5-gate execution chain + hold-to-approve + audit ledger.** The market governs agents with identity, quotas, and post-hoc logs; we gate *before* execution and keep a per-attempt ledger. This is the one mechanism no platform ships and the one regulated deployments need. It also composes with the market's own API seams — Cortex/Genie-style "return SQL, execute separately" is precisely the contract our runner already implements with teeth.
- **The Brief as the product.** Our blueprint's line — "the durable product is not the chat; it's the analysis artifact" — is independently validated by Hex's traction, Julius's stamp-to-notebook, deep-research citation reports, and the arXiv artifacts paper. Claim-structured Briefs with evidence chips + witness panels + snapshot pinning remain unoccupied territory.
- **Guardrails as first-class, queryable, enforced nodes** with refusal-as-explanation (`validate_sql_plan` naming the violated guardrail and its provenance) — see white space #5.

**Table stakes we lack (buyers will assume these exist):**

1. **Verified-query escrow + badge loop** (VQR/Trusted-Assets pattern), including auto-mined candidates from usage queued for steward review. Our `human_approval` weight-10 facts and curation queue are the backend; the promotion action and the badge are missing.
2. **A metric execution surface for non-agent consumers + interchange compatibility** — JDBC/SQL-protocol or REST metric queries a BI tool can consume, and OSI-format import/export (plus awareness of Agents Schema) so our Metric contracts interoperate with, rather than compete against, the standard the whole vendor list just signed.
3. **Bootstrap + continuous learning + feedback capture + eval UI** — auto-proposal of graph facts from usage with human review (their Autopilot/Ontology equivalents), an in-surface "that's wrong" → witness-statement correction flow, an in-product golden-set/benchmark runner (Genie ships ≤500-question eval sets with an explaining judge), plus on-behalf-of identity into BigQuery and a Slack/Teams surface (Genie/Spotter/Lightdash/Tableau all live in chat platforms already).

**Vocabulary to adopt / avoid:**

- *Adopt:* **"context layer"** (the category term — qualify ours as *provenance-typed* context), **"grounding"**, **"verified queries" / "trusted assets"** (use the standard names when we build the escrow), **"semantic model"** for the OSI-compatible slice, **"on-behalf-of"**, **"answer abstaining"** (Snowflake's term for principled refusal), **"agent observability."** Speak OSI and Agents Schema fluently — interop credibility now lives there.
- *Avoid:* "the first agentic analytics platform" (claimed by Cube, Salesforce/Tableau, and ThoughtSpot within months of each other); absolutist accuracy claims ("100% accurate," "hallucination-free" — ThoughtSpot's "if tokens are correct, SQL is 100% accurate" shows how these get lawyered); bare "knowledge graph" as the headline (data.world proved the accuracy and still exited as an acqui-feature — lead with what it does: provable answers); "catalog" (invites feature-matrix comparison with Atlan); "copilot" (Microsoft owns the word).

### 4. Steal / avoid list

**Steal (with source):**

1. **Verified-query promotion loop** — retrieval-grounding on human-verified Q→SQL pairs; exact-match returns the verified SQL directly; provenance exposed in the API (`verified_query_used`); one-click "save as verified query"; usage-mined candidates queued for review ([Snowflake VQR](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst/verified-query-repository), [suggestions](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst/verified-query-suggestions)). Our version: "Promote to verified" on any Brief claim → `human_approval` fact → chip upgrade.
2. **Trusted-asset labeling on the answer** — the response names the vetted artifact that produced it, and parameters remain editable within the vetted template ([Genie](https://docs.databricks.com/en/genie/trusted-assets.html)). Our analog: claims resolved via a skill's metric contract carry the skill's identity, not just a tier.
3. **TrustCheck-style inline flags at SQL-authoring time** — endorse/warn/deprecate colors on referenced objects while the query is being drafted ([Alation](https://www.alation.com/docs/en/latest/welcome/BestPractices/UseTrustFlagstoProceedwithConfidence.html)). Our analog: witness-tier chips per referenced table/column in the SQL preview, before the approval gate.
4. **Term-mapping review** — show how words mapped to model entities and let users correct the *mapping*, not the SQL ([ThoughtSpot "Review business terms"](https://docs.thoughtspot.com/cloud/10.8.1.cl/spotter-getting-started)); Wren's editable "thinking steps" generalize this to the whole reasoning chain ([Wren](https://docs.getwren.ai/oss/guide/home/adjust_answer)). Perfect fit for our `disambiguate_term`/synonym machinery.
5. **"Ask for review" + coach-from-failure** — end users escalate a suspect answer into a steward queue; the fix persists as instruction/reference ([Genie monitoring](https://docs.databricks.com/aws/en/genie/monitor), [Coach Spotter](https://docs.thoughtspot.com/cloud/latest/spotter-coach)). Our version writes a correction witness statement so the *graph* remembers, not a prompt.
6. **Eval sets in-product, built from real usage** — Genie's ≤500-question benchmarks with a judge that explains failures and one-click "Add as benchmark" from chat; Lightdash builds evaluations from real threads ([Genie](https://docs.databricks.com/aws/en/genie/benchmarks), [Lightdash](https://docs.lightdash.com/guides/ai-agents)). Ship our golden-set harness inside the steward console with "add this Brief to the eval set."
7. **Deterministic-insight split** — statistics compute the facts, the LLM only narrates, and the product says so ([Tableau Pulse](https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm)). Adopt the framing for our sandboxed computations: numbers from code, words from the model.
8. **Session debug drawer / observable agent** — a dedicated inspector on every AI session ([Omni Blobby](https://omni.co/demos/20250808)); ours opens the witness panel + tool-call trace per claim. Pair with an immutable event table for agent traces ([Snowflake AI Observability](https://docs.snowflake.com/en/user-guide/snowflake-cortex/ai-observability)) — our ledger should be queryable the same way and double as an eval corpus ([Databricks payload logging](https://docs.databricks.com/aws/en/ai-gateway/)).
9. **Per-tool grants on the MCP server** — access to the server ≠ access to tools ([Snowflake managed MCP](https://www.snowflake.com/en/blog/managed-mcp-servers-secure-data-agents/)); adopt as we add riskier tools, with OAuth per the June 2025 MCP spec.
10. **Graph bootstrap agent with human review** — auto-proposed semantic objects land in a review queue, never in production ([Semantic View Autopilot](https://www.snowflake.com/en/blog/semantic-view-autopilot/)); our curation queue already exists — add the proposer, and steal Genie Ontology's *authority-weighting inputs* (author, usage, certification-proximity, freshness) as candidate witness signals we already know how to price.
11. **Query-logs-as-agent-context** — DataHub's `get_dataset_queries` serves real SQL from logs to agents ([docs](https://docs.datahub.com/docs/features/feature-guides/mcp)); validates our gold-SQL witness — expose it not just as fused facts but as retrievable exemplars.
12. **"Stamp" reproducibility** — one click converts an AI answer into deterministic, re-runnable computation ([Julius](https://julius.ai/docs/notebooks/reproducibility-in-notebooks)); our snapshot-pinned Brief is the stronger version — make the re-run affordance visible.

**Avoid (industry failure modes):**

1. **Chat transcript as the terminal product** — answers that evaporate; the leaders are already routing around it (Hex artifacts, Pulse digests, cited research reports). Keep the Brief primary.
2. **Auto-modeling without review** — Autopilot-class self-built semantics shipped straight to production recreate the accuracy debt they claim to fix; keep human curation as the write gate (Snowflake itself routes Autopilot suggestions through review).
3. **Binary "verified" as the only trust state** — it hides staleness and partial corroboration; keep tiers and add recertification decay (stale certification rot is a known catalog failure; note Databricks added *deprecation* signals to Genie spaces for this reason).
4. **Unfalsifiable accuracy marketing** — private-eval "90%+" claims invite the scrutiny Snowflake/AtScale numbers get; publish the golden set and methodology (AtScale's public leaderboard and dbt's open benchmark repo are the honest versions).
5. **RBAC-equals-safety thinking for agents** — permission pass-through does nothing about prompt-injected exfiltration via tool chaining (Supabase MCP incident) or runaway spend; gates + budgets + ledger + injection-aware tool design are the answer.
6. **MCP tool sprawl** — exposing graph primitives instead of task-shaped verbs makes agents flail; dbt's tool families, Cube's structured requests, and BSL's constrained JSON all converge on our MCP spec's existing tenets. Also: don't ship unauthenticated agent endpoints (Malloy Publisher's own README warns of this).
7. **Grounding on raw schema because it demos fast** — the consistent 10–51% floor across every benchmark (and 0% on hard schemas) is the cautionary tale; never fall back to ungrounded generation silently.
8. **Standalone-layer economics** — the metrics-layer wave died unsellable without a surface (Stancil's "economic failure"; Looker Modeler's shelving). Our surface is the Brief + MCP; keep the graph attached to it, never sold bare.
9. **Betting against the platform bundlers** — Snowflake/Databricks give semantic views, chat, and MCP away with the warehouse. Independent survival = cross-platform provenance + execution governance + artifact surface: the three things the platforms structurally won't build first.
